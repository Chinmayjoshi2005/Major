6. SYSTEM ARCHITECTURE & TECHNICAL HIGHLIGHTS
================================================================================

1. SINGLE WORLD, DUAL MODE PARADIGM:
   - Houses both "Explore Mode" (cinematic camera, scroll-based inspection) and "Game Mode"
     (WASD movement, jump, sprint, third-person camera, colliders) on a shared 3D canvas.
   - Eliminates engine re-initialization overhead when transitioning between inspection and gameplay.

2. ASSET PIPELINE (BLENDER AS SOURCE OF TRUTH):
   - Blender 3D Model (`campus.blend`) -> Rigged & Collidered in Unity -> Exported to Unity WebGL.
   - Mesh naming conventions (`room_001` ... `room_045`) strictly mapped to JSON database records.
   - Output builds utilize Brotli compression (.data.br, .wasm.br, .framework.js.br) for minimal footprint.

3. GRAPH-BASED INDOOR PATHFINDING ENGINE:
   - Modular `CampusPathfinder` class modeling university layout as a weighted graph (NavNodes & NavEdges).
   - Computes Dijkstra shortest path from campus spawn entrance (`N-ENT-01`) to any room/faculty target.
   - Calculates distance in meters and parses human-readable step-by-step waypoint directions.
   - Triggers cross-floor transfer modal when user selects a destination on a different level.

4. REAL-TIME SEARCH & FILTERING DOCK:
   - High-contrast Neo-Brutalist search panel with instant reactive matching.
   - Filter by categories: All, Rooms/Classrooms, Departments, and Faculty Members.
   - Floor-level filtering: Ground Floor, 1st Floor, 2nd Floor, 3rd Floor, 4th Floor.

5. ENGINE-TO-WEB COMMUNICATION BRIDGE:
   - Complete architectural isolation between 3D runtime layer and web business logic.
   - Encapsulated within React 19 client components with fullscreen API listeners and keyboard traps.

7. KEY ENGINEERING CHALLENGES & SOLUTIONS (INTERVIEW PREPARATION)
================================================================================

Q1: How did you deliver complex 3D graphics in the browser without slow load times?
Answer:
"High-polygon 3D models and game engines typically bloat initial web page load times.
I solved this with a multi-layered optimization strategy:
1. In Blender, I applied Draco mesh compression (level 6) and optimized geometry.
2. For the Unity WebGL build, I enabled Brotli compression, compressing the WebAssembly runtime
   down to ~9MB and data down to ~45MB.
3. On the web side, I implemented lazy loading with Next.js dynamic mounting and custom loading
   skeletons, so the initial web bundle loads in milliseconds while the 3D assets stream asynchronously."

Q2: How does the indoor navigation system work across multiple floors?
Answer:
"I modeled the university floor plan as a weighted directed graph where vertices represent
entrances, junctions, corridors, stairs, and room doorways, and edges represent passable paths.
I implemented Dijkstra's shortest-path algorithm in TypeScript using an adjacency list.
To handle multi-story navigation, vertical stair and elevator transitions are encoded with a 1.5x
penalty multiplier to favor horizontal travel when possible. When a destination on a different floor
is selected, the UI prompts a floor-transfer dialog and automatically updates the active level view."

Q3: Why did you choose Next.js 15 and a Neo-Brutalist design system?
Answer:
"Next.js 15 provides modern App Router architecture, excellent performance with React 19, and
built-in route optimization. For the UI, college map tools are often cluttered and unreadable on mobile.
I chose a Neo-Brutalist design language because its high contrast, bold typography, hard borders,
and distinct color-coded badges make critical spatial information (floor numbers, room types,
contact details) immediately readable even while overlaid on interactive 3D graphics."

Q4: Why Dijkstra instead of A* for pathfinding in this project?
Answer:
"Dijkstra was the optimal architectural choice here because our indoor navigation graph is
sparse (<500 nodes) with non-negative edge weights. Dijkstra executes in under 5 milliseconds
on client hardware without needing complex Euclidean heuristic tuning required by A*. However,
the graph adjacency architecture is modular, so an A* heuristic can be dropped in seamlessly if
the campus scales to multi-building outdoor-indoor campus grids."
